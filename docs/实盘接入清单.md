## 一、前置概念（30 秒看懂）

| 名词 | 说明 |
|---|---|
| **QMT** | 券商提供的量化交易客户端。粤开证券用的是迅投 QMT |
| **miniQMT / 极简模式** | QMT 的一种启动模式，只提供 API 接口、不弹界面策略框。**必须用它** |
| **xtquant** | QMT 自带的 Python 库，本系统靠它下单/取行情。装 QMT 时就有了，但要手动拷进 Python |
| **userdata_mini** | QMT 极简模式的工作目录，连接时必须填这个**绝对路径** |
| **LIVE_PENDING** | 已连实盘、但**每一笔委托都要人工点确认**的安全档位。首笔必须用它 |

## 二、操作步骤

### 步骤 1 · 开通量化权限 + 安装 QMT

1. 联系粤开证券客户经理，开通**量化交易权限**（一般需资产门槛，如 50 万）。
2. 在粤开官网/客户经理处下载 **QMT 客户端**（迅投 QMT，不是普通版交易软件）。
3. 安装到一个**不含中文和空格**的目录，例如 `D:\QMT`。
4. 记下安装目录下的 **`userdata_mini`** 完整路径（例：`D:\QMT\userdata_mini`）——第 4 步要填。

### 步骤 2 · 安装 xtquant

**已完成 ✅** —— 已通过 pip 装好 `xtquant 250807.1.2`（迅投官方发布，34MB，自带 DLL）：

```bash
py -3.12 -m pip install xtquant
# 或走镜像：-i https://pypi.tuna.tsinghua.edu.cn/simple
```

**验证：**

```bash
py -3.12 -c "import xtquant; from xtquant.xttrader import XtQuantTrader; print('OK')"
```

> ⚠️ 装好 xtquant ≠ 能连。它只是一个客户端库，**必须本机有 QMT 客户端在运行**才能连上
> （实测报错：「无法连接xtquant服务，请检查QMT-投研版或QMT-极简版是否开启」）。见步骤 3。

#### 如果你用的是 **exe（不是源码）**

exe 有自己的内置 Python，`pip install` 到系统 Python **不会**让 exe 用上 xtquant。
同时 xtquant 自带原生 DLL，不适合打进 exe（会引发打包冲突）。所以 exe 采用**外挂加载**：

把 `xtquant` 文件夹放到 **exe 同级的 `libs/`** 下即可：

```
选股神AI\
├─ 选股神AI.exe
├─ libs\
│   └─ xtquant\          ← 解压出来的 xtquant 目录放这里
└─ config\
```

获取方式（任一）：
```bash
# 1) 从已装好的环境拷
cp -r "C:/Users/49447/AppData/Local/Programs/Python/Python312/Lib/site-packages/xtquant" \
      "dist/选股神AI/libs/"

# 2) 或直接下载 wheel 解压
pip download xtquant -d /tmp/xtq --no-deps
# 解开 .whl（本质是 zip），取出里面的 xtquant/ 目录
```

系统启动时会自动把 `libs/` 注入 `sys.path`（见 `config/settings.py`
的 `_extend_sys_path_for_external_libs`）。

> **已完成 ✅** —— `dist/选股神AI/libs/xtquant/` 已就位（92 MB / 186 文件，
> 版本 `xtquant_250807`）。实测 exe 自检输出：
> ```
>  ✅ xtquant 已安装
>       ...\dist\选股神AI\libs\xtquant\__init__.py xtquant_250807
> ```
> 重新获取（升级/换机器时）：
> ```bash
> cp -r "C:/Users/49447/AppData/Local/Programs/Python/Python312/Lib/site-packages/xtquant" \
>       "dist/选股神AI/libs/"
> ```

> 用自检脚本确认是否生效：
> `dist/选股神AI/选股神AI.exe --run-script scripts/check_live_ready.py`

> ⚠️ **排查提示**：若自检仍报「xtquant 未安装」而 `libs/xtquant` 明明存在，
> 检查 `scripts/check_live_ready.py` 是否在任何 `import xtquant` 之前导入了
> `config.settings` —— 路径注入发生在该模块的模块级代码里，晚一步就无效。

#### ⚠️ 源码配置 ≠ 打包版配置（容易踩的坑）

打包后 `CONFIG_DIR` = **`<exe 同级>/config/`**，与源码的 `config/` 是**两套独立目录**。
在源码目录里存的账号、改的风控参数，exe **读不到**。需要把这些文件搬到
`dist/选股神AI/config/`：

| 文件 | 作用 | 缺失后果 |
|---|---|---|
| `.salt` | 密钥盐 | **没有它 `broker_accounts.enc` 解不开** |
| `broker_accounts.enc` | 券商账号（密文） | 自检报「未保存任何券商账号」 |
| `deepseek.yaml` | AI 对话接口配置（含 api_key） | AI 解读/问答功能不可用 |
| `broker.yaml.template` | 券商配置模板 | 仅模板，影响小 |
| `trading_guard.yaml` / `watchlist.json` | 风控参数 / 自选池 | 首次运行会**自动播种**，无需手动 |

> `.salt` 与 `broker_accounts.enc` **必须成对**拷贝 —— 密钥由
> `PBKDF2(内置_KEY, .salt)` 派生，盐不匹配就解不出来（不是机器绑定，同机器换目录无妨）。

**已自动化 ✅** —— `build_exe.py` 新增 `_sync_runtime_config()`，
每次打包自动把上表前 4 个文件补到 `<exe>/config/`（**只补缺失、绝不覆盖**，也**绝不**打进 exe）。
手动搬一次也行：

```bash
for f in .salt broker_accounts.enc deepseek.yaml broker.yaml.template; do
  cp "config/$f" "dist/选股神AI/config/$f"
done
```


### 步骤 3 · 启动 QMT 极简模式并登录

1. 打开 QMT 客户端 → 登录方式选 **「极简模式」**。
2. 用资金账号 `260000125091` 登录交易。
3. **保持客户端一直开着**——xtquant 连的是本机已登录的 QMT 进程，关掉就断。

> 若自检脚本报「未检测到 QMT 客户端进程」，就是这一步没做或没登录。

### 步骤 4 · 在系统里补齐账号信息

打开「💹 量化自动交易 → 券商账号登录」：

1. 顶部选 **「💹 实盘模式」**。
2. 选中账号 `yuekai_5091 (260000125091)`。
3. 展开 **「✏️ 设置 / 修改该账号的 QMT 路径」**：
   - 点 **🔍 自动检测** —— 系统会扫描本机自动找到 `userdata_mini` 并保存（推荐）；
   - 或手动填入步骤 1 记下的路径（如 `D:\QMT\userdata_mini`），点 **💾 保存路径**。
   - 保存路径**不会清空密码**（该 bug 已修复）。
4. 点 **🔗 连接**。成功会显示「✅ 已连接 粤开证券 · 实盘」。

命令行等价做法（自动探测并回填）：

```bash
py -3.12 scripts/check_live_ready.py --autofill
```

> **账号文件位置**：`config/broker_accounts.enc`（打包后为 **exe 同级 `config/`**）。
> 密码用本机 `.salt` 派生密钥加密，**重装/重建 exe 不丢账号**；换机器需连同 `.salt` 一起拷贝。

### 步骤 5 · 首笔走 LIVE_PENDING（关键安全闸）

连接到实盘后，**不要直接开全自动**：

1. 到「⚙️ 设置 → 🛡️ 交易安全中枢」。
2. 点 **arm_live()** 生成一次性令牌。
3. 在确认框输入令牌 → **confirm_arm(token)**。
4. 目标模式选 **LIVE_PENDING**（逐单人工确认）——**不要选 LIVE**。
5. 跑一次扫描，逐笔检查「预览 → 审批 → 执行」，确认下单价格/数量/方向无误。
6. 连续若干笔人工核对无误后，再考虑提升到 **LIVE**（全自动）。

**Kill Switch**：任何异常，立即点熔断。熔断状态会持久化，重启仍保持停手；
若曾进过实盘，解除熔断后会**强制回到 PAPER**。

## 三、风控参数（改完即生效，无需重打包）

配置文件：`config/trading_guard.yaml`（打包后为 **exe 同级 `config/`**，运行时读取）

| 参数 | 默认 | 含义 |
|---|---|---|
| `max_portfolio_drawdown_pct` | 8.0 | 组合峰谷回撤熔断线(%) |
| `max_daily_loss_pct` | 3.0 | 单日最大亏损比例(%) |
| `max_daily_loss_abs` | 5000 | 单日最大亏损金额(元) |
| `max_positions` | 20 | 最大持仓只数 |
| `max_single_position_pct` | 0.30 | 单票最大仓位占比 |
| `max_sector_pct` | 0.50 | 单一行业最大集中度 |
| `min_order_interval_sec` | 2.0 | 两笔委托最小间隔(秒) |
| `max_orders_per_minute` | 10 | 每分钟最大委托数 |
| `confirm_timeout_sec` | 300 | 待确认委托超时自动撤销(秒) |
| `sizing_method` | fixed_fractional | 仓位算法：固定比例/波动率目标/凯利 |

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 「连接失败：QMT路径不存在」 | 路径没填或写错 | 步骤 4，点「🔍 自动检测」或填 `userdata_mini` 真实路径 |
| 「无法连接xtquant服务，请检查QMT…是否开启」 | QMT 客户端没开/没登录 | 步骤 3（xtquant 本身已装好） |
| 「连接失败：请检查 QMT 客户端是否启动」 | QMT 没开/没登录极简模式 | 步骤 3 |
| 登录了但自动交易没反应 | 未连接/未武装 | 确认状态条显示「实盘」+ 安全中枢非 OFF |
| `DLL load failed` | xtquant 依赖 QMT 本地 DLL | `bin.x64` 加入 PATH，或用 QMT 自带 Python |
| 改了 `trading_guard.yaml` 没生效 | 改错了目录 | 认准 **exe 同级 `config/`** 那份 |
