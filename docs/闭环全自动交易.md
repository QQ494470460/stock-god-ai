# 闭环全自动交易

> 目标：让系统**自己转起来** —— 收盘选股、盘前出计划、盘中执行、收盘结算、推送日报，全程无人值守。

## 一、闭环长什么样

```
 ①盘后 18:30  刷新数据
 ①盘后 18:45  AI 选股 → 每日推荐  ┐
 ①盘后 18:45  推荐 → 交易计划      ┘  ← 新补的"桥"
 ②盘前 09:15  闭环引擎读计划，备好目标组合
 ③盘中 09:30  每 30s 一个周期：
                同步账户/持仓 → 熔断监控 → 止盈止损 → 目标调仓 → 下单(经安全中枢)
 ④收盘 15:05  结算当日盈亏 → 写日报 → 推送
 └──────────── 回到 ①，循环往复 ────────────┘
```

**改造前的问题**：选股在收盘后跑，交易在盘中跑，但两者之间**没有桥** ——
盘中买入候选读的是人手维护的 `watchlist.json`，跟模型当天选的票完全脱节。
所谓"全自动"其实只有半截。

**本模块补齐的部分**：交易计划（把选股结果变成目标组合）+ 闭环引擎（按计划调仓）+ 结算日报。

## 二、四个新组件

| 文件 | 职责 | 关键点 |
|---|---|---|
| `src/trading/trade_plan.py` | 选股结果 → 交易计划（目标组合 + 权重） | 权重上限与风控口径对齐；计划过期自动作废 |
| `src/trading/rebalance.py` | 计划 vs 持仓 → 买卖意图（纯函数） | 可完整单测；先卖后买；现金底线；整手；T+1 |
| `src/trading/loop.py` | 闭环引擎（状态机 + 主循环 + 结算） | 一切下单必经安全中枢；断线/熔断自动冻结 |
| `scripts/run_loop.py` | 无人值守常驻入口 | 同一套引擎，脱离看板跑；演练状态隔离 |
| 本文件 + UI「🔁 闭环全自动」页 | 配置与可视化 | 预演/演练/启停 |

配套改动：
- `src/trading/guard.py`：新增 `risk_exit`（纪律性离场绕过"评分仍高不卖"）、
  `explicit_quantity`（**计划定数量、guard 定准否**）、`account()`/`positions()` 公开访问、
  `rebaseline_peak()`（净值基线重置）+ `baseline_account`（账号切换自动重置）
- `src/trading/executor.py`：`check_stop_conditions(positions, prices)` 支持注入（纸交易/离线可用）；
  `execute_ai_signal(..., risk_exit=)` 同步语义
- `src/scheduler/auto_scheduler.py`：`job_daily_pick` 顺手产出交易计划
- `config/settings.py`：新增 `TradingLoopConfig`

## 三、怎么用

### 1. 先演练（强烈建议）

打开「💹 量化自动交易 → 🔁 闭环全自动」：

1. 先到「🔐 登录管理」点 **连接**（模拟模式无需账号）
2. 在「⚙️ 闭环参数」勾上 **🧪 演练模式（只预演不下单）**
3. 点 **🔄 手动跑一周期** —— 看它算出的调仓意图是否合理
4. 点 **▶️ 启动闭环** 让它按周期自己跑

演练模式下**不会产生任何真实委托**，纸账户也不会被改动。

### 2. 纸交易实跑

关掉演练模式，保持安全中枢为 **PAPER**（默认）。此时闭环会真实地在纸账户上
买卖、持仓、止损、结算 —— 零真实资金，但全流程完整。

### 3. 实盘

必须满足：
1. 券商已连接且是实盘（见 `docs/实盘接入清单.md`）
2. 安全中枢两步令牌武装：`arm_live()` → `confirm_arm(token)`
3. **首笔留在 `LIVE_PENDING`**（逐单人工确认），核对无误后再提到 `LIVE`

### 4. 无人值守（`scripts/run_loop.py`）

看板里的闭环跑在 Streamlit 的 daemon 线程上，**关掉应用就停**。要做到真正无人值守，
用独立的常驻入口（与看板是同一套 `TradingLoop` + `RiskSupervisor`，只是没有界面）：

```bash
py -3.12 scripts/run_loop.py --preview        # 只预演「本该下什么单」，退出
py -3.12 scripts/run_loop.py --once           # 只跑一个周期
py -3.12 scripts/run_loop.py --dry-run        # 演练：连纸单都不下
py -3.12 scripts/run_loop.py                  # 常驻（默认纸交易）
py -3.12 scripts/run_loop.py --until-close    # 常驻，收盘结算完自动退出
py -3.12 scripts/run_loop.py --live           # 实盘（需已两步武装，否则拒绝启动）
```

打包版 exe 同样可用：

```bash
dist/选股神AI/选股神AI.exe --run-script scripts/run_loop.py --until-close
```

配合调度器（每个工作日 18:45 自动选股 + 生成次日计划），就是完整的无人值守闭环。

**演练零副作用**：`--dry-run` / `--preview` 会把风控状态文件隔离到
`data/loop_rehearsal/`，绝不写生产状态。
（教训：曾有一次演练把 `halted=true` 写进真实状态文件，把用户的实盘风控冻住了。）

#### 净值基线失真了怎么办（换账号 / 出入金 / 纸账户重置）

回撤熔断是拿「当前权益」比「历史峰值」。如果账户资金基数发生了**与交易无关**的
变化（换券商、纸账户重置、出入金），旧峰值就显得异常高，首 tick 就会误判巨额回撤
并熔断 —— 实测：纸账户 10 万 对上遗留峰值 100 万 → 报 89.95% 回撤直接停手。

```bash
# 把基线重置为当前权益；--resume 顺便解除熔断
py -3.12 scripts/run_loop.py --rebaseline-peak --resume
```

重置会写进 journal（`event=rebaseline_peak`），事后可审计。

**账号明确切换时会自动重置基线**（状态文件记录 `baseline_account`，
纸账户为 `PAPER`，实盘为资金账号）—— 但仅当新旧账号都明确时才自动；
信息不足时**宁可熔断**，绝不静默放宽风控。

## 四、安全边界（务必读）

| 机制 | 说明 |
|---|---|
| **一切下单必经安全中枢** | 未传 guard 时引擎自动构建一个默认 **PAPER** 中枢 —— 忘了配也绝不裸奔 |
| **默认纸交易** | `GuardConfig.default_mode = "paper"`，重启绝不自动进实盘 |
| **空计划 = 按兵不动** | 模型某天没选出票（或数据故障）**不会**触发清仓，避免一次抖动清空组合 |
| **计划不能突破风控** | 计划给的股数只是"想要多少"；单票上限 / 可用现金 / T+1 可卖量仍由 guard 硬封顶 |
| **权重上限对齐** | 计划单票权重被压到 `guard.max_single_position_pct`（默认 30%），避免"要 45% 只准 30%"的错配 |
| **纪律优先于观点** | 止盈止损 / 调仓清仓走 `risk_exit=True`，不被"AI 评分仍高不卖"拦下；涨跌停/停牌/T+1 照旧 |
| **熔断冻结一切** | 组合回撤 / 单日亏损触线 → `halted`，闭环立刻停手并推送告警 |
| **单周期限量** | `max_orders_per_tick`（默认 10）防止异常时雪崩式下单 |

## 五、参数速查（`config/settings.py` → `TradingLoopConfig`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `scan_interval_sec` | 30 | 主循环周期（秒） |
| `auto_build_plan` | True | 自动生成/刷新交易计划 |
| `max_positions` | 10 | 目标持仓上限 |
| `cash_reserve_pct` | 0.10 | 现金保留比例（底线） |
| `weight_cap` | 0.30 | 单票权重上限 |
| `weighting` | equal | 权重分配：`equal` 等权 / `score` 评分加权 |
| `enable_rebalance` | True | 目标组合调仓开关 |
| `enable_stop_orders` | True | 止盈止损开关 |
| `band_pct` | 0.25 | 调仓容忍带（偏离 25% 内不动手） |
| `min_trade_amount` | 5000 | 最小交易金额（元），过滤碎单 |
| `max_orders_per_tick` | 10 | 单周期最大下单数 |
| `settle_hour/minute` | 15/5 | 收盘结算时刻 |
| `notify` | True | 事件/日报推送（受 `notifier` 总开关约束） |
| `dry_run` | False | 演练模式 |

止盈止损阈值在 `GuardConfig` / `RiskConfig`：
`stop_loss_pct=-5%`、`stop_profit_pct=15%`、`trailing_stop_pct=-3%`。

## 八、已知边界

- 实盘下单仍依赖 QMT 客户端与 xtquant（见实盘接入清单），本模块不改变这一点。
- 结算依赖账户净值快照；若当日无 tick（如停牌全仓），结算仍会按最后价格执行。
- **无人值守**：看板内的闭环依赖应用进程存活；要脱离看板请用
  `scripts/run_loop.py`（常驻进程 / 计划任务）。调度器只负责盘后产计划，
  不驱动盘中执行。
- 涨跌停/停牌拦截发生在 `guard` 层，被拦截的意图会计入报告的 `n_blocked`。
- 净值基线的自动重置仅在「资金账号明确切换」时触发；出入金、纸账户重置等
  同账号内的基数变化需显式 `--rebaseline-peak`（设计如此：静默放宽熔断线更危险）。
