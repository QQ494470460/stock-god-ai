# 选股神 V2 改造说明

> 生成日期：2026-10-08
> 起因：用户反馈"预测的一点都不准"

---

## 一、先说结论

原来的系统**无法产出任何一个可信的准确率数字**。这不是调参能解决的问题，
而是评估链条本身是断的。所以"预测不准"这件事，在旧系统里甚至无法被证伪。

本次改造分两层：
1. **让准确率变得可测量**（评估链条修复）
2. **在可测量的基础上，用正确的方法论提升实际效果**（管线重写）

---

## 二、诊断发现的问题（按严重程度）

### 致命级

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 1 | 全量数据 fit scaler | `trainer.py:170` | 验证集的均值方差参与标准化，未来信息泄漏进训练 |
| 2 | SMOTE 在切分前对全量数据过采样 | `trainer.py:177-178` | SMOTE 插值生成合成样本，时序结构被破坏，"时间序列验证"名存实亡 |
| 3 | 按行切分实为跨股票切分 | `train.py:117` + `TimeSeriesSplit` | `pd.concat` 把各股票历史首尾相接，切出来的是"前200只股票" vs "后100只股票"，而非时间先后 |
| 4 | 22 批预测 0 批验证成功 | `data/prediction_history.json` | 历史准确率面板从7 月至今一直空白 |
| 5 | 验证用"今天减5天"反推日期 | `tracker.py:127` | 预测只在交易日产生，周末/节假日必然匹配不上，验证永不触发 |
| 6 | 基准代码解析错误 | `tracker.py:101` | `"000300.SH"` 被解析成 `sz000300`（平安银行），异常被`except: return 0.0` 吞掉 → 超额收益恒等于平均收益 |
| 7 | max_drawdown 按收益排序后累加 | `tracker.py:239-248` | 降序排列后曲线单调不降，`peak == cumulative` 恒成立 → **回撤永远输出 0.0** |
| 8 | 缓存文件名不含日期区间，短区间调用覆盖写坏全量缓存 | `fetcher.py:126,186` | 追踪回测请求最近30天 → 全量历史缓存被永久压成 30 天 |

### 严重级

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 9 | 14 个基本面特征恒为 0 | `fetcher.py:341-348` | 财务数据获取失败被静默吞掉，模型输入 14 个常数列，且掩盖了数据缺失事实 |
| 10 | 标签定义为绝对涨跌 | `engine.py:494` | 模型 85% 的学习目标是"猜大盘走向"，而大盘方向几乎不可预测 |
| 11 | 三分类天花板极低 | 实测 | 涨 30.4% / 震荡 36.7% / 跌 32.9%，**全猜"震荡"就有 36.7%** |
| 12 | 备用源强制不复权 | `fetcher.py:233-241` | 新浪源失败时静默切换价格体系，但缓存文件名仍是 `_qfq` |
| 13 | 幸存者偏差 + ST 时点偏差 | `fetcher.py:57-103` | 退市股全部剔除；用当前名称过滤历史样本 |
| 14 | 回测零成本零约束 | `quantitative.py:379-425` | 无手续费/滑点/T+1/涨跌停，信号与成交同 bar |
| 15 | 交易日历缺失 | `fetcher.py:142-147` | `weekday() < 5` 冒充交易日，法定节假日全部误判 |

## 三、实测证据（`scripts/diagnose.py`）

用 120 只股票、250266 个样本跑出来的结果：

### 3.1 因子方向与直觉相反

```
因子                平均IC      IC_IR
rev_5d短期反转     +0.0406    +4.23
ret_20d 20日动量    -0.0796    -8.42     ← 反向指标
vol_20d  波动率     -0.0897    -7.72     ← 低波动才是好的
```

**A股中期动量是反向指标。** 按 `ret_20d` 选 Top20，
年化跑输约 15%。项目当前的核心特征恰好是动量族，
也就是说模型在努力预测一个市场中期已经反转掉的规律。

### 3.2 数据越多模型越差

| 训练样本量 | macro-F1 |
|-----------|----------|
| 30,000    | 0.592    |
| 350,120| 0.442    |

样本增加 11.7 倍，模型效果**下降 15 个百分点**。
配合 CV 第 5 折 accuracy 从 0.54跌到 0.39，
说明模型主要在记忆噪声而非学习规律。

### 3.3 历史宣称指标 vs 真实水平

| 指标 | 历史日志宣称 | 实际 |
|------|------------|------|
| F1 | 0.68 | CV accuracy 仅 0.53 |
| 已验证准确率 | 面板显示中| **0 / 22 批** |

0.53 vs 天花板 0.367 的差距，就是数据泄漏的幅度。

## 四、V2 改造内容

### 4.1 新增文件

| 文件 | 作用 |
|------|------|
| `src/models/labeling.py` | 标签构造 + 横截面因子预处理 + 评估指标 |
| `src/models/factors_v2.py` | 因子面板构建（含逐日截面 rank） |
| `src/models/trainer_v2.py` | Walk-forward 泄漏安全训练器 |
| `src/models/predictor_v2.py` | V2 推理，输出可解释的相对强弱排序 |
| `src/models/tracker_v2.py` | 重写的命中率度量链条 |
| `scripts/diagnose.py` | 诊断脚本（只读） |
| `scripts/train_v2.py` | V2 端到端训练管线 |

### 4.2 训练流程的六处修正

| # | 原做法 | V2 做法 |
|---|--------|---------|
| 1 | 标签=未来5日绝对涨跌 | 标签=未来5日**超额收益**的**截面分位**（5档） |
| 2 | 特征=单股110维混杂量纲 | 特征=因子面板，逐日**截面 rank** 归一化到 (-1,1) |
| 3 | 按行切分 | 按**日期** walk-forward，train 日期 < valid 日期 |
| 4 | 全量 fit scaler | 每折内**只用 train 段** fit，valid 段只 transform |
| 5 | 全量 SMOTE | **class_weight**（不动样本，时序安全） |
| 6 | 评估=accuracy/F1 | 评估=**RankIC / IC_IR / TopN超额 / Sharpe / 回撤** |

### 4.3 为什么改成"相对强弱"

选股真正要预测的不是"这只股票会不会涨"，而是
"这只股票比同一天的其他股票强多少"。

实测数据支撑：
- 全市场 5 日收益标准差 **6.37%**
- 剥离市场共同波动后剩 **5.46%**

如果标签用绝对涨跌，模型 85% 的学习目标其实是"猜大盘走向"，
而大盘方向几乎不可预测 → 模型只能学噪声。
改用截面分位后，市场 beta 被自动剥离，
剩下的才是选股 alpha。同时每天各档占比天然均衡，
不再需要 SMOTE（也就避免了它对时序的破坏）。

### 4.4 为什么因子要做截面处理

不做截面 rank，模型会把"全市场都在跌"误判为"这只票强势"——
因为原始因子值里混杂着市场整体水平。
逐日独立排名后，模型学到的才是跨股票通用的相对强弱规律。

### 4.5 度量链条的四处修正

| 问题 | V2 做法 |
|------|---------|
| 用"今天减N天"反推日期 | 遍历每条历史记录，逐条检查是否走够 horizon 个交易日 |
| 基准代码错误 + 异常静默吞掉 | 用 `sh000300` 指数接口，失败时**明确告警**而非归零 |
| 回撤按收益排序后累加（恒为0） | 按真实时间顺序累计净值算回撤 |
| 未快照预测日价格 | `save_predictions` 时快照价格，验证时直接用 |

### 4.6 修复效果：度量链条从0 变成 15

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 已验证预测批数 | **0 / 22** | **15 批 / 281 个样本** |
| 总体准确率 | 无法测量 | **45.2%** |
| 平均收益 | 无法测量 | **+0.69%** |
| 超额收益 | 恒等于平均收益（假） | **+5.99%**（真实） |

修复后的历史准确率 **45.2%** 印证了本文档开头的判断：
选股场景下这个数字就在50% 附近徘徊，
根本不存在"调参调到 70%"的可能性。

**注意**：修复后的 15 条记录都是**旧记录**，没有价格快照，
基准价靠事后查表取得（前复权数据会被未来除权改写），
所以超额收益可能偏乐观。新流程（`daily_recommend_v2.py --track`）
记录了价格快照，5 个交易日后验证才完全准确。

从那15 条记录还能看到一个有趣的现象——**评分高低与收益无关**：

| 评分档 | 2026-08-01 | 2026-07-13 |
|--------|-----------|-----------|
| ≥80 分 | +7.40% | **-5.52%** |
| 60-80 分 | +7.24% | -2.38% |

高分档并不比次高分档更赚钱，有时还更差。
这正是旧 `scoring.py` 人为拼接评分公式的致命缺陷——
它跟真实收益没有必然联系。V2 已弃用该公式。

## 五、V2 实测结果

用 200 只股票、2018-01 ~ 2026-09 数据（41.7 万样本）跑出来的**真实样本外表现**：

```
样本外 RankIC      +0.0489
IC_IR              +15.36
Top20 单期超额     +0.1907%   (每5日，相对全市场均值)
超额胜率           54.4%
超额最大回撤       -35.75%
五档分类准确率     27.7%    (随机猜=20%)
样本外样本数198418
```

**这些数字怎么解读：**

| 指标 | 评价 |
|------|------|
| RankIC +0.0489 | 多因子模型样本外能到 0.05 就算不错，达到交易门槛 |
| IC_IR +15.36 | 信号极其稳定（逐日 IC 的一致性很高） |
| 单期超额 +0.19% | 5日赚 0.19% 跑赢大盘，约合年化 9.5%，**未扣手续费** |
| 超额胜率 54.4% | 略高于五五开，说明有微弱但持续的优势 |
| 五档准确率 27.7% | 比随机猜(20%)好，但**别指望这里有 50%** |
| 最大回撤 -35.75% | 相对基准的累计回撤，真实且不美化 |

**必须扣掉的现实成本：**
- 5日调仓 × 50 次/年 × 双边 0.15% ≈ **年化 15% 成本**
- 也就是说 +0.19%/期的毛超额，扣掉成本后可能所剩无几
- 这也是为什么 V2 不再输出"年化收益"——那个数字会骗人

### 与旧系统的对比

| 指标 | 旧系统宣称 | V2 真实样本外 |
|------|-----------|-------------|
| F1 / 准确率 | 0.68 | 27.7%（五档）/ RankIC 0.049 |
| 历史已验证批数 | 0 | 15 批 / 281 样本 |
| 超额收益 | 假（=平均收益） | +5.99%（真实测算） |
| 数据泄漏 | 3 处 | 0 处 |

## 六、怎么用

```bash
# 1. 诊断：先看数据里到底有什么信号（只读，不改任何东西）
py -3.12 scripts/diagnose.py

# 2. 只看因子体检：确认哪些因子真的有预测力
py -3.12 scripts/train_v2.py --max-stocks 300 --factors-only

# 3. 完整训练：walk-forward + 样本外评估
py -3.12 scripts/train_v2.py --max-stocks 300

# 4. 每日选股（--track 会记录价格快照，供日后验证）
py -3.12 scripts/daily_recommend_v2.py --top 20 --track

# 5. 验证历史预测，产出真实准确率
py -3.12 scripts/verify_v2.py
```

> 该项目使用系统 Python 3.12（`py -3.12`），依赖齐全。
> 完整训练约需12 分钟（200 只股票），建议后台运行。

## 七、使用 V2 结果时的注意事项

**必须理解的一点：即使 V2 训练完成，准确率也不会变成 70%。**

量化选股的现实预期：
- 单因子 |RankIC| 通常在 0.02 ~ 0.06
- 多因子模型样本外 RankIC 能到 0.05 左右就算不错
- 五档分类准确率 25~30% 属正常（随机猜是 20%）

如果你看到任何 AI 系统宣称"准确率 80%+"，那几乎一定是数据泄漏或者过拟合了。

**这个系统的价值不在于预测涨跌，而在于：**
1. 把全市场压缩成有统计依据的相对强弱排序
2. 每个信号都附带历史样本外 IC，让你自己判断信不信
3. 提供真实可验证的绩效追踪，而不是拍脑袋的评分

**V2 明确不做的事：**
- 不预测"明天涨还是跌"
- 不给"78.5 分"这种没有实际含义的评分
- 不报未扣成本的年化收益

## 八、未修复 / 遗留问题

以下问题本次未处理（超出"改预测准不准"的范围），但建议后续处理：

| 问题 | 影响 | 建议 |
|------|------|------|
| 幸存者偏差 | 退市股全被剔除，模型没见过"垃圾股归零" | 引入已退市股票 + point-in-time 股票池 |
| 前复权改写历史 | 2015年训练出的模型，历史特征形态会随除权变化 | 改后复权或保存除权日快照 |
| 停牌/涨跌停 | 停牌股K线跳空，rolling 指标失真；涨跌停无法成交 | 特征层前向填充，回测层过滤 |
| 真实交易日历 | `weekday()<5` 冒充交易日，节假日全误判 | 接交易所日历 |
| 手续费与冲击成本 | 当前 +0.19%/期 是毛超额，成本可能吃掉大部分 | 加入万5佣金 + 千1印花税 + 冲击成本 |
| LSTM 模块 | 已闲置 4 个月且从未集成 | 建议直接移除 |
| 数据陈旧 | 本地数据最新为 2026-09-18 | 补齐后重新训练验证 |
| 股票名称 | 选股结果显示的是代码而非名称 | 补股票名称表 |
